## 3. Mass model [V]
consensus/core/src/mass/mod.rs:
- size = tx estimated serialized size (l.15-60): 2+8+inputs+8+outputs+8(locktime)+20(subnet)+8(gas)+32(payload hash)+8+payload. Input: 36 outpoint+8+sigscript+8 seq (+2 compute_budget if v>=1). Output: 8+2+8+spk (+2+32 if covenant).
- compute_mass = size*1 + 10*Σ(2+spk_len of outputs) + script_mass; v1: script_mass = 100 grams * Σ input.compute_budget; v0: 1000 grams * Σ sigop_count. (l.~232-262; params mass_per_tx_byte=1, mass_per_script_pub_key_byte=10, mass_per_sig_op=1000, params.rs:625-627)
- transient_mass = size*4 (TRANSIENT_BYTE_TO_MASS_FACTOR, constants.rs:31). Coinbase: 0,0.
- storage_mass (KIP-9, generalized): C=STORAGE_MASS_PARAMETER=10^4*10^8=10^12 (constants.rs:26). plurality p = ceil((63 + spk_len + 32 if covenant_id)/100). harmonic_outs = Σ C*p²/amount (integer division per output). If |O|plurality==1 OR (<=2 inputs and (ins_plurality==1 or both ==2)) relaxed: max(0, harmonic_outs - Σ C*p²/amount_in). Else max(0, harmonic_outs - ins_plurality*(C / max(1, Σamt/ins_plurality))). Overflow -> None = "incomputable" = reject. Covenant UTXO counts +32 B (KIP-20 §6) [V].
- Storage mass is committed in tx.storage_mass (hashed in sig hash, not txid per KIP-9) and checked == recomputed: tx_validation_in_utxo_context.rs:126-133 (WrongMass / MassIncomputable).
- Block check (consensus/src/pipeline/body_processor/body_validation_in_isolation.rs:67-100): SEPARATE sums per dimension: Σcompute<=500,000, Σtransient<=1,000,000, Σstorage(committed)<=500,000 (the old "mass=max(compute,storage)" in KIP-9 text is superseded). Plus lanes: <=50 distinct non-coinbase subnet lanes/block, Σgas per lane <=1,000,000,000 (constants.rs:98-100).
- Normalization (for mempool/template): cofactor_i = L_compute/L_i -> storage 1.0, transient 0.5, reference 500,000. normalized_max = max(compute, ceil(0.5*transient), storage).

## 4. Limits [V] (params.rs:616-631, tx_validation_in_isolation.rs, txscript/src/lib.rs)
- max inputs 1000, max outputs 1000 (non-coinbase). Coinbase outputs <= ghostdag_k+2.
- Sigscript per input <= 250,000 bytes (was 10,000 pre-Toccata). SPK script <= 10,000 bytes (max_script_public_key_len). Standard-mempool output SPKs must classify as P2PK/ECDSA/P2SH (ScriptClass != NonStandard); for P2SH input sigops <= 15.
- Script engine: MAX_SCRIPTS_SIZE 1,000,000; MAX_SCRIPT_ELEMENT_SIZE 1,000,000; MAX_OPS_PER_SCRIPT 1,000,000; MAX_STACK_SIZE 244 (combined data+alt stack); multisig <=20 keys (lib.rs:77-85). Numbers 8-byte (KIP-10). Note: the per-script 1M ceilings are in practice bounded by transient mass (1M mass = 250 KB for whole block).
- tx version: <=1 (TX_VERSION_TOCCATA); v1 forbids sigop_count, v0 forbids compute_budget; gas only on v>=1 and non-native/non-coinbase subnet; outputs value in (0, MAX_SOMPI=29e9 KAS]; no duplicate inputs; covenant bindings require v>=1.
- Compute budget: u16 per input, 1 unit = 100 grams = 10,000 script units; free allowance per input = 9,999 script units (units.rs). Metering (runtime_resource_meter.rs): sigop = 1000 grams (100,000 units); pushed bytes charged 1 unit/byte (lib.rs:613); hashes: blake2b 2 units/byte, blake3 1, sha256 1 (opcodes/mod.rs:60-71); ZK: Groth16 140,000 grams (=3 per block), R0Succinct 250,000 grams (zk_precompiles/tags.rs:29-87). Exceeding -> ExceededCommittedScriptUnits (script fails -> tx invalid). Other ops are NOT separately charged (only through size/pushed bytes) [V as far as I read; full per-op audit not done -> [U] for cost of OpCat/OpMul etc.].

## 5. Opcodes [V] (KIP-17/20 text + crypto/txscript/src/opcodes/mod.rs)
Common failure rules: all idx/start/end args are i32 -> usize via i32_to_usize (negative fails); out-of-range input idx -> InvalidInputIndex, output idx -> InvalidOutputIndex; each introspection op errors InvalidSource unless run in a TxInput script source (not in standalone scripts). Substr ops fail if start>end, out of bounds, or end-start > 1,000,000.
Covenant (KIP-20) , all invalid before Toccata:
- 0xcf OpInputCovenantId(idx): pushes 32B covenant_id of UTXO spent by input idx, or ZERO_HASH (32 zero bytes) if none. Works on ANY input idx (siblings too) [V l.1318] -> answers kips#46 Q1.
- 0xd5 OpOutputCovenantId(out_idx): output's declared covenant_id or ZERO_HASH. 0xd6 OpOutputAuthorizingInput(out_idx): authorizing_input index or -1. These see genesis AND continuation outputs.
- 0xcb OpAuthOutputCount(input_idx): number of CONTINUATION outputs authorized by that input (outputs with binding.authorizing_input==input_idx AND that input's UTXO covenant_id == binding.covenant_id). 0 if none. Error if input_idx >= #inputs.
- 0xcc OpAuthOutputIdx(input_idx, k): tx-output index of k-th such output; error InvalidAuthCovOutIndex if k >= count; error if input_idx out of range.
- 0xd0 OpCovInputCount(covenant_id): # inputs whose UTXO carries id (0 if none/ZERO_HASH). 0xd1 OpCovInputIdx(id,k): k-th input idx, error InvalidCovInIndex if k>=count. 0xd2 OpCovOutputCount(id): # CONTINUATION outputs with that id (outputs whose authorizing input carries same id); genesis outputs excluded. 0xd3 OpCovOutputIdx(id,k): error InvalidCovOutIndex if out of range. Stack arg is a 32-byte Hash (non-32B behavior [U]).
- Consensus (not opcode) covenant checks, CovenantsContext::from_tx (txscript/src/covenants.rs:98-160): authorizing_input must be < #inputs (AuthInputOutOfBounds); genesis group (authorizing_input, id) must equal BLAKE2b-256("CovenantID" key) over outpoint + auth_outputs(idx,value,spk ver,len,script) else WrongGenesisCovenantId -> tx invalid. KEY: consensus does NOT force a continuation output to keep the same script or amount, nor force the covenant script to emit the output: scripts must enforce it (KIP-20 states this). A covenant UTXO can be spent with outputs carrying no binding (lineage ends) unless script forbids. Output with an id that is neither continuation nor valid genesis is uncreatable.
- OpChainblockSeqCommit 0xd4(block hash): errors BlockAlreadyPruned / BlockNotSelected (not on selected chain from POV) / BlockIsTooDeep (beyond accessor depth; see kip-0021/seqcommit-accessor.md - depth value not extracted [U]).
KIP-17 introspection: OpTxVersion b2, OpTxInputCount b3, OpTxOutputCount b4, OpTxLockTime b5, OpTxSubnetId b6, OpTxGas b7, OpTxPayloadSubstr b8, OpTxInputIndex b9, OpOutpointTxId ba, OpOutpointIndex bb, OpTxInputScriptSigSubstr bc, OpTxInputSeq bd (8B LE), OpTxInputAmount be, OpTxInputSpk bf, OpTxInputDaaScore c0 (DAA score of block that CREATED the spent UTXO), OpTxInputIsCoinbase c1, OpTxOutputAmount c2, OpTxOutputSpk c3, OpTxPayloadLen c4, OpTxInputSpkLen c5/Substr c6, OpTxOutputSpkLen c7/Substr c8, OpTxInputScriptSigLen c9. Bytes: OpCat 7e (fails > 1M), OpSubstr 7f, OpInvert 83, OpAnd/Or/Xor 84-86 (fail on unequal lengths), OpMul 95, OpDiv 96, OpMod 97 (div/mod by zero and i64::MIN/-1 fail; mul overflow fails), OpNum2Bin cd (size<=8 and fits), OpBin2Num ce, OpBlake2bWithKey a7 (key<=64B), OpBlake3 d9, OpBlake3WithKey da (key == 32B), OpCheckSigFromStack d7 / ECDSA d8 (32B msg hash). OpLeft/Right/LShift/RShift stay disabled. OpZkPrecompile a6 (tag 0x20 Groth16/BN254, 0x21 RISC0 succinct).
IMPORTANT for oracle design: OpCheckSigFromStack EXISTS (KIP-17 d7). Issue kips#46 claims "no opcode to verify a signature over an arbitrary message" - that is outdated post-Toccata [V]. No opcode reads a UTXO without spending it (KIP-10 text) [V by absence in opcode list].

## 6. Time / DAA / locktime semantics [V]
- Scripts can read: tx lock_time (OpTxLockTime), input sequence (OpTxInputSeq), creation DAA score of any spent UTXO (OpTxInputDaaScore), CLTV/CSV, seq commitment of chain blocks. Scripts CANNOT read current block DAA score / timestamp / median time directly; only via lock_time bounded by consensus.
- Tx lock_time (tx_validation_in_header_context.rs): 0 = final; < 500,000,000,000 (LOCK_TIME_THRESHOLD) = DAA score; >= = unix ms time. Tx is final iff lock_time < ctx (strict) where ctx = block DAA score (for DAA type) or past-median-time (time type), OR all input sequences == u64::MAX. Mempool uses virtual DAA score / virtual past median time (processor.rs:1195,1298).
- OpCheckLockTimeVerify b0: pops <=8B LE; fails NumberTooBig if >8B; fails if type mismatch (tx lock_time vs stack on opposite sides of threshold); fails if stack_lock_time > tx.lock_time; also fails if the input's sequence==MAX (opcodes/mod.rs:874-925, tail partly read). So script can enforce "tx.lock_time >= T" and the consensus finality rule forces block DAA/median-time > tx.lock_time. Net: earliest-spend guarantee only; there is NO "latest/deadline" check (cannot prove "now < T").
- OpCheckSequenceVerify b1: relative; sequence bit63 (SEQUENCE_LOCK_TIME_DISABLED) set on the tx input -> fail; compares low 32 bits; stack operand with bit63 set = NOP. Consensus relative lock (check_sequence_lock): input rejected if utxo.block_daa_score + (seq & 0xffffffff) - 1 >= pov_daa_score (relative DAA-score based, i64).
- Time unit: DAA score ticks ~10/s on mainnet (10 BPS), median time window per constants.rs.

## 9. How miners fill near-full blocks (kips#46 "Q5", the issue's Q5 = "several-hundred-input tx reliably includable?"; the user's "Q4" is Argent-script-size in the issue text) [V]
Issue #46 body: Q3 = compute-mass ceiling on input count, Q4 = SilverScript script size limits, Q5 = includability of several-hundred-input tx. Comments are by the issue author (cyprox) = third-party data; their measured N=640/530 claims are [S]/[U].
Reference node behavior (mining/src/mempool/model/frontier.rs, frontier/selectors.rs, feerate_key.rs; transactions_pool.rs:220 Policy max_block_mass = reference = 500,000 normalized):
1. Only "frontier" = txs with no unconfirmed mempool ancestors are candidates.
2. Weight = (fee / normalized_mass)^3 (ALPHA=3). Mass = max(compute, 0.5*transient, storage), single scalar.
3. If frontier total mass <= 500k: take all (best-first). If > 4x block limit: sample in place by weight (20% oversample, MASS_LIMIT_FACTOR 1.2, stop at gap <=5%) then greedy SequenceSelector tries in sampled order, skipping txs that don't fit the remaining gap. Between 1x and 4x: MutatingTreeSelector, weighted random draws without replacement, deferring too-big candidates, stopping after 8 consecutive mass-null attempts.
4. Lane/gas limits enforced per selection; rejected txs (consensus rejection at template build) are released and selection retried (max 5 attempts).
=> Selection is probabilistic fee-density-weighted, not strict greedy by feerate. A very large (e.g. 400k-mass) tx has the same weight as a small tx of equal feerate, but is less likely to fit the remaining gap once the block partially fills; large txs are disadvantaged under congestion unless feerate is clearly above the pool. This is node default policy; miners may use any selection (consensus only checks limits). No guaranteed inclusion rule anywhere [V by absence].
